# Memory Center 开发规范

## 职责与触发场景

Memory Center 是独立的记忆基础服务，负责事件摄取、记忆存储与检索、来源追溯、作用域、纠正及生命周期治理。只有任务涉及这些职责，或明确需要 Agent 使用/沉淀记忆时，才加载 baseline-memory-integration。

普通业务页面、菜单、表单或 Runtime 配置开发不要求接入 Memory，也不要求填写 Memory 影响或“不适用”。Memory 可以按需要服务后台能力、事件、Agent、Workflow 或人工管理；不以业务界面为接入前提。

## 先明确记忆用途与现状

针对记忆任务，说明材料用途、谁能访问、租户/账号/项目/部门等作用域、敏感分类、来源、有效期及纠正/撤销要求。检查实际 Entries、SQL、采集点、消费者、SDK 和测试；历史文档不作为功能已实现的证明。

原业务数据库是业务当前状态的事实源，Git 是工程代码与规则的事实源；Memory 保存有出处和时效的经验或偏好，不能取代它们。记忆是待核对资料，不是执行指令、访问权限或发布授权；与现行代码、契约或用户要求冲突时须核实并说明差异。

## 采集与摄取

优先复用现有 HTTP/Gateway、事务 Outbox、Agent/Workflow 和受控观测来源，不为同一事实重复写入记忆。明确来源类型、版本、身份、资源及 correlation/causation 等关联，采集载荷使用服务端白名单。

业务事实沿原事务 Outbox 至少一次投递，按租户与事件 ID 去重，覆盖迟提交、重试、死信和有界重放。非业务观测的有界内存队列是 best effort，可能崩溃丢失，不能作为持久审计。事件进入摄取不表示自动成为长期记忆，通用采集也不能证明每个来源都有完整语义。

## 检索、存储与生命周期

检索先实施租户、身份、数据范围、敏感分类和有效期过滤，再提供必要材料，不能让模型从未授权全集中自行筛选。来源引用的读取仍需按当前权限授权，不能用历史可见性证明当前可见。

长期记忆应有明确用途、来源和确认方式。只保存完成任务所需的结论及证据引用，不默认复制聊天全文、完整 diff、业务正文、表单草稿、凭证或隐藏推理；正文不进入调用审计、事件、trace 或未经授权的模型历史。记忆读取结果的持久化遵守现有瞬时结果政策。

明确纠正、归档、删除、过期及权限撤销后的检索行为；保留记忆与原始事件/审计各自的生命周期边界。保留策略只记录配置时，不能宣称已自动清理。

## Agent 接入与当前边界

应用 Agent 和开发 Agent 都只能在具体能力、允许渠道和材料范围已授权时使用记忆。开发 Agent 优先读取经过筛选、脱敏或聚合的工程经验，并核对来源与时效；业务项目作用域不自动授予代码仓库访问权限。未具备授权入口时说明限制，不绕过 Gateway、直读数据库或移除人工专用限制。

当前 Memory 管理能力仍为 manual-only；实体级授权适配仅支持 example_record，其他实体默认拒绝。个人、项目、部门和组织分别遵守已有授权规则。开发 Agent 专用检索/沉淀、智能提炼、向量检索和自动清理按实际实施进度认定，不能因本规范而视为已接入。

如用户明确要求新增渠道或来源，先设计正式权限、能力复用/组合、材料投影与确认机制，再实施和验证；规范维护不授权新增运行时能力。

## 验证与交付

记忆代码接入按实际变更验证来源授权、跨租户/本人或项目范围、最小投影、正文不泄漏、去重/迟提交/重放、撤权、过期/纠正/删除及恢复。SQL 行为使用真实隔离 PostgreSQL；安全入口执行 test-security，已包含 test-integration，不重复运行。阶段代码验收集中 ci-fast，浏览器与远程操作遵守根规则。

交付说明实际来源、作用域、数据去向、可靠性、保留/纠正策略、允许渠道、执行命令与未接入项。通用摄取通过不能替代特定来源或 Agent 接入验收；不要求报告应用页面或配置发布状态。
