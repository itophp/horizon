# 工程文档

继承根规则。docs/source-specification.md 保留原始来源，不重写来掩盖差异；当前架构、开发路由和执行规则以最新用户要求及现行 AGENTS/Skill/CI 为准。

架构/工具/命令变更同步受影响的规范、agent-tooling 任务矩阵及 agent-policy 清单；只有 README 中的稳定介绍确实受影响时才同步对应章节。明确“已实现/已验证/待决策”，本地检查不能写成远程 CI 已通过。

README 是稳定的项目入口文档，只维护项目定位、当前架构、核心能力、使用入口和文档导航，不作为开发日志。普通功能完成、阶段推进、测试验收、规则调整或聊天结束不默认修改 README；每次改动内容、阶段进度、测试结果与未完成项记录到对应实施文档或验收记录。更新稳定说明时直接修改所属章节，不在文末追加调整记录。README 必须以开源协议章节结尾，协议后不得追加功能、进度或实施说明。

长期规则不放本次聊天的阶段限制；历史验收可记录日期和当时结果。规则链接必须可解析，不复制整份第三方手册；优先链接版本化项目规则和官方资料。

文档/规则变更运行 make check-rules；只有同时改代码/契约/脚本时，再按 testing.md 选择对应门禁。不得为了文档维护强制启动无关慢测试。
