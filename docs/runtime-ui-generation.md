# Runtime UI 设计与生成标准

本标准补充现有 design-system、page-templates、ui-component-guidelines、ui-interaction-patterns，不另建视觉主题。适用于代码 Agent 与声明式设计 Agent；后者只能选择已注册布局、字段展示和组件，不生成任意 CSS/JS。结构校验通过不能证明视觉质量。

## 生成前：设计说明

在候选说明或实施记录填写以下六项，未支持的设计明确列为缺口：

1. 使用者、任务、业务对象：谁在什么情境完成什么事。
2. 信息排序：第一眼的对象名称/状态、决策所需辅助信息、可延后内容。列出实际字段，不以数据库顺序代替设计。
3. 主操作与次操作：一个主要操作组；筛选、视图设置为次级，危险操作有确认。
4. 模式与原因：列表/详情/表单/分析/工作台；参考现有同类页，说明为何适配。
5. 组件映射：已有 Provider/Action/字段展示/可信组件及固定版本；缺失项与代码扩展边界。
6. 验收情境：真实数据、长文本、空/错/载入、无权限、窄屏、双语与浅暗主题。

文章示例：作者查找文章并进入详情；标题是识别锚点，状态辅助判断，版本和评审是次要元数据；新建为主要操作，搜索/状态/排序为查询组，列设置为视图工具。采用紧凑列表而非统计仪表盘；分页总数不是全局状态统计。

## 生成中：八项规范

| 系统 | 可执行约束 |
|---|---|
| Design System | 引用 styles/index.css、styles/admin.css 的语义色和半径；Geist 及系统中文回退。背景/面板/浮层三层，文字 foreground/muted-foreground，错误 destructive；不引入每页色板。间距采用 4/8/12/16/20/24/32px；普通面板不叠阴影，浮层才使用现有 shadow。字号正文 14、辅助 12、分组 16、页标题 24px 为默认目标，现有公共组件数值优先；同层同字重，不用全部加粗制造层次。 |
| Layout System | 复用 console 壳、PageHeading 和内部滚动，不重复导航。列表随可用宽度，正文阅读区约 65–80 字符；编辑表单按字段组收窄。标题→查询→结果→分页顺序，关联对象不纵向堆屏；不得为填满空间添加无业务用途模块。 |
| Component System | 使用本地 Base UI/shadcn API；Input/Select/Checkbox/Dialog/Button 保留语义与焦点行为。Card 只分组独立内容，不包每个字段。Tab 仅切换同级视图；普通数据比较使用 Table，不套卡片网格。复杂区域以注册可信组件扩展，保持业务无关的引擎。 |
| Page Pattern | 列表：识别字段优先，查询组与命令分开，行命令菜单，分页绑定 URL；详情：摘要、状态、动作、分组字段/子对象标签；短表单 Dialog，长编辑独立页；仪表盘只有真实授权聚合才放 KPI，图表必须服务比较/趋势任务；工作台按待办优先级组织，连续处理才用主从布局。具体准入见 page-templates。 |
| Interaction Pattern | RHF/Zod 就地显示字段错误；提交 pending 禁重复，失败保留输入且可重试，成功反馈与 query invalidation。Dialog 聚焦任务，Drawer 保留上下文，退出返回焦点；不另写浮层状态机。首次加载/后台刷新/空集合/筛选无结果/失败分别表达；骨架保持布局，不用假数据。 |
| Visual Quality | 第一屏可识别对象、主要动作和当前状态。查询项靠近，命令与查询留组间距；同组控件等高、基线对齐。优先字段获得更大可读宽度，显式配置宽度和用户列偏好优先。不用渐变、装饰图标、假统计、每区 Card 作为美化手段。状态有文字，不仅靠颜色；色彩数量不当作质量指标。 |
| Responsive Design | 至少检查 1440、768、390px；平板先换行查询区，手机搜索独占一行，其余控件可换行；主从视图单列保留返回路径。表格局部横向滚动，页面无横向溢出；不得隐藏关键动作或挤压表单。长标题、中文和英文分别检查。 |
| Accessibility | 一个主 h1、分组 h2；输入有可访问名称，错误关联字段；可见焦点，Tab/Enter/Escape 可操作，弹窗关闭恢复焦点。普通文本对比度至少 4.5:1，UI/大字至少 3:1；触控目标至少 24px，移动常用动作目标 44px；尊重 reduced-motion，200% 缩放不丢信息。 |

## 生成后：评审与修正

先验证候选结构/引用/授权，再在隔离只读预览中检查；发布仍按 Runtime 人工发布流程。代码 Agent 检查真实路由，浏览器必须符合当次授权和仓库暂停规则。

每项记录「通过/问题/未验证 + 证据」，不只给一个主观总分：信息优先级、组件语义、间距对齐、文本溢出、状态反馈、键盘焦点、响应式、主题和双语。对每个问题写出文件/组件、观察到的现象及确定修法，再复看相同视口；三轮同根因无解停止盲改，报告阻塞。无浏览器权限时只能报告代码检查，不能声称视觉验收。

声明式 Agent 的 validate/diff 只能证明配置和变更，不提供截图、对比度、实际焦点证据；缺乏浏览器工具必须明确移交视觉检查，不能把工程 Skill 文件存在当作运行时模型已加载。
