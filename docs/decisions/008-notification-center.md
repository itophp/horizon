# ADR 008：独立通知中心与 Markdown 通知

通知中心不占用侧栏菜单，入口是顶栏右上角的铃铛图标（未读角标）；页面包含收到的通知、已发送以及投递记录，不再把「发起通知」作为标签页。收到的通知列表只显示标题与通知时间（保留未读底色与「标为已读」操作），点击标题行进入独立详情页 `/notifications/:id` 查看完整正文与附件；已发送列表默认收起正文，只显示标题、收件人数与时间，需要时再展开内容，避免长消息撑满列表。SMTP 凭证/渠道参数仍由系统设置统一管理；投递记录、连接测试/本人测试发送属于通知中心。保持既有后台界面、浅暗主题、中英文和内部滚动结构。

人工发送使用独立正式 `notifications:send`（可配置数据范围，不可临时申请）；旧角色不会自动得到它。收件人选择接口只暴露此权限范围内的最小选项，不要求同时授予账号管理读取权限。支持账号/部门/公司/企业混选，部门含子部门；组织目标只有其全部有效成员均在发送者范围内才可选，禁止静默部分群发。后端预览去重人数，发送时重新展开并校验，固定接收账号及有效部门归属。重叠目标按账号去重，最多 200 个目标、10,000 个账号。组织后续新增成员不会补收到旧通知。

人工通知作为独立 announcement 领域记录，不伪造临时权限请求或 gov_events。主体、接收快照、文件绑定、站内投递记录和可选 SMTP 队列同一事务提交；客户端 UUID 与内容摘要用于幂等，相同键不同内容拒绝。已发送只由原发送者及原发送部门上下文读取，投递管理复用 notifications:read/retry 数据范围。审计只记录通知 ID/人数，不记录完整正文和邮箱。SMTP 继续使用持久化退避队列，至少一次投递；收件账号、归属、偏好在投递前复验。站内/邮件偏好继续有效。

人工通知对接收账号跨当前部门可见，但必须仍拥有发送快照绑定的有效归属；临时权限事件消息仍遵守其申请/审批部门上下文。读取、标记已读和附件下载均按账号/租户隔离。移除归属、停用账号/部门/公司/企业后，绑定失效；再次加入相同归属会恢复该历史通知的访问，不授予原业务操作权限。

正文为 Markdown，最多 50,000 字符，标题最多 200 字符且禁止换行。前端复用 NotificationMarkdown（react-markdown + remark-gfm），不执行原始 HTML/MDX，不放开危险 URL；外部图片不自动加载。上传最多 20 个附件，复用现有文件服务的类型/大小校验。插入语法为 `file:ID` 的 Markdown 文件链接或图片引用；ID 必须同时出现在发送附件列表，且文件由发送者拥有、属于同租户、用途为 attachment。已绑定文件不能从附件管理删除。邮件发送纯文本 Markdown，文件引用转向需登录的应用通知详情入口（message 查询参数），关闭站内偏好也能按接收人绑定读取邮件详情。

「发起通知」是通知中心的按钮入口，跳转独立页面 `/notifications/compose`（需 `notifications:send`，无权限显示访问提示），不再占用通知中心标签页；发送成功后回到 `/notifications?tab=sent`。编辑区集成开源 MDXEditor（MIT，Lexical + mdast，双向 Markdown），工具栏只保留撤销/重做、段落样式（正文/标题/引用）、加粗斜体下划线、删除线、列表、链接、表格和分隔线；上传并插入文件、源码/差异/预览浏览模式均不提供，编辑区即所见即所得结果，正文渲染仍以 NotificationMarkdown 为准。编辑器通过 `suppressHtmlProcessing` 关闭原始 HTML 处理，链接仅接受 http(s)/mailto，界面文案与新增工具栏项全部走 i18next，浅暗主题复用后台 tokens。发送页不再提供附件上传入口，历史通知中的附件仍按原规则渲染与下载。

通知附件通过 `/api/auth/notifications/:id/files/:fileId` 读取，SQL 校验收件人、有效归属及通知与文件绑定，复用共享存储服务按原 profile 读取。收件人不需要全局 files:read，也不能据此读取其他通知或未绑定文件。发送者的编辑/已发送预览仍使用自己具备的通用 files:read；不扩大通用文件权限。通知及文件上传不是公开静态目录。

扩展消息/文件业务时同步 baseline-shared-capabilities、baseline-security、目录规则和允许/拒绝测试；不在业务页面裸发 SMTP 或复制文件读取实现。迁移只追加 00008，保留既有临时权限事件、消息与投递记录。

验收可使用独立 playwright.governance.config.ts，避免并行功能工作占用默认服务/产物。SMTP 邮件详情通过 notificationsMessage 与 notificationsAttachment 的生成 SDK 消费，站内列表偏好不会阻断本人从邮件进入已授权详情；这不开放他人消息。
