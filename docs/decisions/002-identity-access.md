# 002 — 身份、组织与权限管理

状态：已实现，2026-10-28。遵循现有 Goa、PostgreSQL/sqlc、Casbin、Orval 和 React 技术栈。

## 身份和组织

工作区 tenant 是最高隔离边界，由服务器从数据库会话解析，不能通过客户端请求头切换。一个工作区可以包含多个企业，企业下包含公司，公司下为树状部门。账号归属一个公司和一个部门，可以关联多个角色。账号名全库唯一，避免未认证登录依赖客户端选择 tenant。

`make bootstrap` 在显式配置的数据库内创建初始企业、公司、两个部门、两个角色及内置管理员；使用事务和 advisory lock，只允许初始化空工作区，重复执行不会重置密码。管理员标记不在写入 DTO 中，不能通过页面复制；内置管理员不能停用或删除。

## 权限合并和数据范围

操作目录为 accounts / organizations / departments / roles 的 read/create/update/delete，另有 `access:manage`。活跃角色的允许规则并集；账号对某个操作的独立 allow **替换该操作继承的数据范围**，独立 deny 则拒绝，inherit 删除覆盖规则。角色策略本身只接受 allow，账号支持 allow/deny。这样账号可以收窄继承的 ALL，而不是只能扩大权限。

六种数据范围：ALL（工作区内全部）、ORGANIZATION（本人公司）、DEPARTMENT（本人部门）、DEPARTMENT_TREE（本人部门及下级）、OWN（本人账号）、CUSTOM（指定部门）。范围在服务端结合真实身份解析，查询和单记录写入同时包含 tenant 与范围条件。OWN 用于账号；在结构资源中不代表创建任意结构的授权。

组织读取会提供当前公司的上下文信息；角色是工作区级配置，持有 roles:read 可读取该工作区角色定义。角色策略修改还必须同时持有对应 roles 写操作和 `access:manage`；分配账号角色/独立权限必须有 `access:manage`。这是可授予其他权限的敏感管理能力，不能授予普通部门管理人员后再期待部门范围限制其授权能力。普通管理员可获得 accounts / departments 的必要操作与数据范围，而不给 access:manage。

前端权限矩阵为每个操作配置允许/继承/拒绝，统一范围选择器将所选范围应用于当前编辑对象的业务操作；API 存储的每条规则仍包含独立 scope。自定义范围必须选中至少一个同工作区部门。账号停用、角色停用和策略变更在下一个请求重新读取数据库时生效；密码重置删除该账号全部会话。

## 会话和请求边界

Argon2id 随机盐哈希，不返回密码或哈希。会话使用 32 字节随机令牌，数据库只保存 SHA-256 摘要，8 小时绝对有效期。浏览器仅保存 HttpOnly、SameSite=Lax cookie；CSRF nonce 只保存在 JS 内存，刷新通过 me 恢复。写入请求同时校验同源 Origin 和 X-CSRF-Token，登录也必须同源。前端 SDK 统一发送凭证与 nonce。

开发仅数字 loopback HTTP 可 COOKIE_SECURE=false；其他监听必须启用 COOKIE_SECURE=true，并通过 HTTPS/可信反向代理访问，代理保留原始 Host。生产数据库、TLS、备份、部署密钥和运行监控仍需部署环境配置。

登录有单进程按来源 IP 的每分钟限额，以及数据库内按账号摘要记录的五次失败/15 分钟锁定；不存在账号也执行密码计算。反向代理来源地址策略和跨实例 IP 限流需要按真实部署拓扑配置。当前审计为结构化请求日志，没有长期合规审计库或操作历史页面；SSO/MFA/邮箱自助找回未实现，页面提供联系管理员重置入口。

## 验证

Go 单元、真实 PostgreSQL 的隔离 schema 集成与 Playwright 浏览器验收分别验证策略合并、六类范围、越权 ID、跨工作区、CSRF、角色/账号停用、密码重置及 CRUD。E2E 使用专用命令创建并清理临时 schema，测试凭证只存在于该 schema。具体执行结果见 docs/verification.md。

后续扩展：两级权限目录和临时申请/审批按 [ADR 003](003-temporary-access.md) 执行。临时允许补充正式权限/范围，账号 deny 仍然优先，审批不会直接修改账号的固定覆盖规则。


多部门扩展由 [ADR 004](004-department-memberships.md) 定义：主/附加部门独立策略，当前部门决定授权；临时授权绑定申请部门，移除归属永久撤销。涉及部门切换或归属变化时以 ADR 004 的最新行为为准。
