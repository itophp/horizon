# 003 — 两级权限目录与临时授权

状态：采用，2026-10-29。在 ADR 002 的正式会话、角色/账号授权与 SQL 范围之上增加临时授权；不复制第二套认证或授权框架。

## 两级目录

`internal/identity/catalog.go` 是权限目录的服务端来源，定义一级 module、二级 function、操作 code、是否允许临时申请及是否可配置范围。Goa 生成 PermissionDefinition，Snapshot 和临时申请工作区返回目录；页面不另造权限代码或自行决定哪些权限可申请。界面使用原生表格的 rowSpan 合并一级模块单元格，二级功能下保留操作授权。

基础管理包含账号、组织、部门、角色；权限管理包含授权配置与临时审批。既有 accounts/organizations/departments/roles 的权限代码保持兼容，不因界面分组改写角色策略。

## 申请与审批

所有已认证且活跃的账号可进入临时权限页，读取公开授权目录及本人公司的最小部门名称目录，提交无权限功能申请或已有功能的数据范围提升。普通账号只读自己的申请。拥有正式 `temporary:approve` 的账号可读取本工作区审批队列和最小部门选择目录，审批他人申请；access:manage 不自动等于审批权限。

默认仅内置管理员有审批能力；初始化的 System administrator 角色不自动加入该权限，之后可按现有角色/账号授权流程显式配置。审批人不能自批，临时授权也不能再次被当成审批授权上限。access:manage 仍是可分配角色/账号权限的敏感全局管理能力。

可选 30 分钟、1/2/4/8 小时、1/3/7 天。从批准时的数据库时间开始计算，申请等待时间不扣减有效期。审批人可调整最终权限、时效和范围，也可拒绝；原始申请权限/时效/理由与最终批准结果分别保存。申请人可撤回待审申请、主动放弃生效授权；审批人可撤销生效授权。

每个获批操作必须属于审批人正式权限，每个获批组织/部门/本人范围必须是审批人正式数据范围的子集。ALL 不得由有限范围审批人授予；有限范围相互比较时使用可信 SQL 关系。审批支持原子 pending → approved/rejected，重复/并发审批只能有一个成功。工作区、申请人、审批人和时间由服务端确定，不能由 DTO 修改。

## 临时授权与正式授权的关系

正式角色合并及账号覆盖继续遵循 ADR 002。生效临时 allow 在这个基础上补充操作和数据范围；账号显式 deny 始终优先。固定权限不会被临时权限覆写或删除，到期/撤销后回到固定权限。

权限配置 access:manage、审批 temporary:approve 和角色策略写入不能临时申请，避免借短期访问留下长期授权。账号的角色/覆盖、用户名/邮箱、密码、状态及组织/部门归属变更，以及组织/部门的状态和树归属变更，还必须通过操作者正式写权限及正式数据范围校验，不能借临时编辑权限留下永久身份/范围提权。临时写权限仍可修改非安全敏感的业务展示字段。角色读取是工作区级配置，只接受 ALL 临时范围；其他功能仍走既有服务和 SQL 范围校验。 scopeConfigurable=false 只用于本来就是工作区级的功能，临时范围固定 ALL；业务数据功能必须保留可信范围解析和 SQL 条件，不能通过关闭该标志绕过范围校验。

批准时将 ORGANIZATION / DEPARTMENT / DEPARTMENT_TREE / OWN / CUSTOM 解析为固定的组织 ID、部门 ID 和账号 ID 集合并存储。账号之后变更部门不会重定向获批范围，之后新增的下级部门也不会自动纳入这次固定授权。ALL 依旧严格限制在当前工作区。

每次认证从数据库加载 status=approved、expires_at>now() 且审批账号仍活跃的记录；没有进程授权缓存。失效由服务端数据库时钟判断，不依赖 UI 倒计时或定时任务。审批人的后续策略变化不重写已作出的审批决定，需要时显式撤销；审批账号停用会使其签发的临时授权停止生效。

## 持久化、审计与验证

00003_temporary_access.sql 新增独立申请表，保留申请者、原始数据、最终授权、已解析范围、审批者/说明/时间、到期时间及撤回/撤销时间和撤销人。审批/撤回/撤销使用带工作区、身份与状态约束的原子 SQL。状态 expired 由读取时计算，授权 SQL 同时排除过期记录。

目录与临时申请最小元数据是有意向已认证账号开放的功能，不代表开放账号、角色或完整部门数据。Cookie、Origin、CSRF、请求体和错误投影复用既有边界。前端只提交申请意图，不能自行激活临时授权。

`make test-security` 中的真实 PostgreSQL 用例覆盖无权限申请、已有范围提升、审批修订、正式上限、自批/行政权限租借拒绝、账号变更后的固定范围、到期/撤销/deny 优先、跨租户及并发审批。前端组件测试验证两级目录/合并单元格与申请权限筛选，Playwright 以真实 API 验证申请和审批界面。


多部门扩展由 [ADR 004](004-department-memberships.md) 定义：主/附加部门独立策略，当前部门决定授权；临时授权绑定申请部门，移除归属永久撤销。涉及部门切换或归属变化时以 ADR 004 的最新行为为准。
