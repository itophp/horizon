# ADR 010：系统设置定时发布

系统设置保存草稿后可安排一次性发布时间，默认一小时后，允许至少一分钟至 365 天后；不扩展为字典定时发布或个人偏好排期。界面沿用草稿/发布历史，增加排期记录、计划时间、状态、完成时间、错误结果和取消。使用设备时区输入并明确提示，转换为带时区的 UTC 瞬时；服务端按数据库时间校验与执行，展示使用现有 Intl 规则。不存在的本地时间不默默纠正。

复用正式 settings:publish 和工作空间 ALL 范围创建/取消，settings:read 和 ALL 范围查看；不增加隐式角色授权或临时发布权。排期只绑定已保存的不可变草稿、基准版本、内容摘要、账号和创建时部门上下文。敏感排期使用 settings.schedule 五分钟单次重新认证证明，绑定当前会话、部门、草稿及版本，在创建排期事务内消费；不能混用立即发布/回退证明，不保存密码或长效证明。

队列持久化在追加迁移 00009 的 gov_settings_schedules，同一草稿仅一条 pending。排期期间立即发布同一草稿被拒绝，须先取消；不同草稿仍可正式发布/回退，到期发现版本冲突则失败，不重放旧配置或自动重新基线。失败或取消后可基于有效版本重新排期；敏感项需重新认证。

后台重建创建者在原部门的可信 Principal，重新检查账号/部门有效性、正式发布权限、ALL 范围、草稿状态/摘要、现行类型/安全/文件/存储消费者与基准版本。新增敏感性若未经确认也拒绝。登录会话到期/退出不删除显式排期意图，但权限或账号失效会阻止执行；不拿旧浏览器会话或临时权限作为后台授权。账号删除保留历史身份，执行失败而非丢失记录。

任务以 FOR UPDATE SKIP LOCKED 持有行锁领取，通过 savepoint 隔离发布失败。配置、版本、审计及 published 结果在同一外层事务提交；崩溃/取消/连接断开回滚后仍 pending，新进程可恢复领取。业务失败记录为 failed 和稳定错误码，不自动覆盖/无限重试；无法提交数据库或服务关闭时保持 pending。不能仅靠前端定时器、内存队列或额外脚本。工作进程运行时每秒处理到期任务，不承诺硬实时；停机期间不执行，恢复后按当前权限和版本补检。

后台权限、文件读取与配置校验共用同一事务查询，避免单连接死锁与跨池校验。接口/差异不返回草稿密文、证明、密码或底层错误；排期 DTO 只给授权管理员任务元数据和脱敏错误。设置消费者继续只读已发布 gov_values，不提前读取排期/草稿。管理页轮询状态，完成/取消后刷新历史及运行时缓存；其他页面沿用现有运行时配置刷新。

验收覆盖未到期/到期、重复/并发、取消/重复取消、版本冲突、单次证明及用途绑定、会话过期、权限/范围收紧、账号停用、跨租户、真实 worker 循环、单连接 Logo 和浏览器排期/刷新保持/取消；所有写入测试在隔离 PostgreSQL，记录于 verification.md。
