# ADR 018：Runtime v2 与声明式动作

日期：2026-11-05。状态：已采纳，M1/M2 实现与验证范围见阶段记录。

文章示例暴露了固定权限、字符串表单、固定主键/版本映射及业务动作重复分派问题。v2 将应用、页面、Provider、创建/编辑命令、表格、布局和动作分离；Entity 和 Capability Definition 保留原职责。Go 模型派生 TS/Zod/能力 Output Schema，装配语义检查独立于结构生成。

数据和动作都绑定固定能力及版本，Runtime 不直连 SQL。通用层只解析受限表达式和当前身份投影；记录范围及业务状态仍在原能力执行。项目以真实插件贡献验证复用，派生字段只读，普通编辑不以状态转移或 revision 存在为条件。

批量动作放回业务模块，逐项经 Gateway，事务不跨能力。网络恢复使用稳定 operationId 与子幂等键；外层信封遵守既有 Gateway 的结果重放语义，不修改全局幂等政策。完整插件持久生命周期与 AI 深度集成另行交付。

取舍：保留显式 Provider/字段映射与可信 Hybrid 插槽，避免把领域逻辑吸入通用 CRUD。静态定义随代码发布；没有新元数据数据库、动态脚本或第二套授权引擎。

详见 [M1/M2 阶段说明](../application-runtime-phase-2.md)。

会话投影追加可选 authorizationVersion，用可信权限/范围摘要区分同代码不同范围的授权上下文。它不是凭证，不包含会话秘密；新授权 profile 发布前清理私有缓存。同版本周期刷新保留草稿。该会话契约通过 Goa/OpenAPI/Orval 生成；业务动作契约仍属于 Definition。
