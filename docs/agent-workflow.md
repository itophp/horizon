# Agent 长期开发工作流

根 AGENTS.md 是入口；任务路由见 [agent-tooling.md](agent-tooling.md)，可执行门禁见 [testing.md](testing.md)。原始规范是需求来源档案，当前用户要求及版本化的 AGENTS / Skill / CI 是持续开发依据。

## 一次功能任务

1. **发现现状。** 检查 Git 与未提交变更，读取目标路径沿途 AGENTS；使用 baseline-feature-development 路由 Skill。检查实际能力目录、实体、SQL、流程定义、页面和测试，不把示例或历史文档当作当前实现的证明。
2. **还原业务过程。** 列出触发者、动作、对象、前后状态、成功条件和失败去向。区分“请求已受理”“AI 判断完成”“人工批准”“业务已完成”，把后台任务与人工页面也算作入口。
3. **消除关键歧义。** 按下节的问题矩阵，只询问现有上下文无法确定且影响业务、安全或外部暴露的事项。合并提问；沿用已答选择。等待时继续不依赖答案的工作，不把超时当同意。
4. **形成架构映射。** 在任务计划、进度说明或必要的设计文档中记录下述最小决策表，不要求每次新增 ADR。先选能力边界与事务，再判断同步组合、Eino Workflow、Graph、ADK；选型缺口明确列出，不能用普通函数悄悄替代用户要求的引擎。
5. **先改唯一源。** 根据实际涉及层修改 Definition、实体、SQL 或 Goa DSL，再生成并实现。编排任务先检查标准 Schema、实际已支持的节点语义、工具输出及恢复机制；原子能力先完成权限、事务和状态约束，流程只经 Gateway 调用。
6. **贯通所有入口。** 接入页面、事件/Trigger、Agent/MCP 允许集合与业务人工任务。前端复用 SDK、Query、表单/表格组件与 i18n；检查状态、原因、等待与失败是否真正可见，而不只检查 API 能否调用。
7. **按不变量验证。** 依据下文建立成功、拒绝、重放、恢复及页面交互用例。普通连续开发累计待验模块；高风险或诊断先做最小定向验证。阶段验收按 testing.md 集中执行并复用有效结果，遵守当前浏览器暂停与授权边界。
8. **核对并交付。** 用实际调用链核对最初决策，报告引擎、流程名称/版本、能力及工具暴露、真实命令/结果、生成影响、兼容性、安全和未执行项。注册了 Layer、ai_runs 或流程目录不等于业务已进入相应引擎。

API 工作流：design → Goa/OpenAPI → 非生成服务/传输 → Orval → UI。数据库工作流：migration/query → sqlc → Repository/事务 → 隔离 PostgreSQL。界面工作流：组件/tokens → 所有语言资源 → 交互/类型/构建 → 需要的真实浏览器流程。

## 能力复用优先：先发现、再复用、最后新增

开发功能前，先把业务动作映射到当前已提供的能力。复用包括业务模块、身份能力、设置/字典/文件/通知等共享能力，以及已有流程、SDK 和 UI 组件；不能只复用框架库，却重新实现已有业务行为。

1. **发现候选。** 搜索实际模块 `Entries()`、共享装配目录、相关 Definition、实体与成功事件、流程定义和测试；有授权运行环境时可读取能力目录。按动作、对象与语义搜索，不仅匹配名称。离线查定义用于设计，不代表当前调用者拥有执行权限；不要为发现能力执行写操作。
2. **核对可用性。** 检查输入输出 Schema/版本、权限与租户/账号范围、风险/审批、幂等、事务/事件、副作用、敏感数据和适配器允许集合。名称相近不等于语义相同；存量绕过 Gateway 或范围过宽的实现不是可复制模板。
3. **按顺序选择。** 已有完整动作直接复用；多个能力可以完成时通过 Gateway 组合；仅缺少兼容字段或语义时在原模块扩展并维护全部消费者。破坏性变化采用明确的新版本或独立能力，不静默修改旧契约。只有实际存在无法复用的独立业务语义时才新增，说明候选与不适用原因。
4. **保持复用边界。** 页面调用现有 capability SDK；Workflow 节点、Agent 工具和能力互调经 Gateway。不复制已有 SQL/业务校验，不 Resolve 后直接执行 Handler，也不为同一个动作按 UI/Agent/MCP 各写一份实现。纯计算函数和明确允许的基础设施/共享内部事务辅助按其原约定复用，不机械注册成能力。
5. **记录并验证。** 在最小架构决策中列出“需求动作 → 已有能力/版本 → 直接复用、组合、扩展或新增及原因”，简短到足以审查即可。复用仍需验证当前用例的权限、字段投影、失败与幂等，不因旧测试通过推定新入口安全；契约变化补兼容与受影响消费者测试。

尽可能复用不意味着扩大已有权限、放宽字段投影、增加纯透传包装或建立万能能力。多个写必须同一事务时，不能通过多次 Gateway 调用拼成假原子事务；按能力组合规范确定原子动作边界。工程上的复用选择由 Agent 基于代码完成，只有业务行为、权限或外部暴露产生实质变化且用户尚未明确时才询问。

## 开发前需要确认的问题

以下是按场景选择的问题库，不是每次全部发给用户的问卷。先查已有会话、需求和代码；用户决定业务意图与暴露边界，Agent 负责框架、文件位置、事务与 Schema 等工程选择。需求已明确时直接实施，不再要求用户批准技术计划。

| 场景 | 仍有歧义时询问用户 | Agent 必须自行核对 |
|---|---|---|
| 动作与完成条件 | 点击按钮表示提交申请还是立即生效？什么状态才允许公开、下载或触发后续动作？ | 状态转移、实体声明、事件事实和页面文案一致 |
| 角色和数据范围 | 谁创建、查看、修改、审核？能否自审？审核员能否看未提交草稿？ | Principal、权限目录、租户/账号/范围 SQL；UI 隐藏不算授权 |
| 业务人工审核 | 审核人如何确定？需独立页面还是现有队列？驳回是否必填原因、是否可修改重提？是否有超时规则？ | 任务归属、决定与版本条件、原因投影、撤权和重复决定；不得默认自动批准 |
| AI 参与方式 | 只需分类建议还是需 Agent 选择能力、多轮调查？哪些材料可发给模型？AI 能否触发业务写入？ | 工具白名单、结果校验、敏感信息与执行边界；用户已要求 Agent 时不能无说明退化为单次模型调用 |
| 不确定与失败 | 模型不可用、词库无效、结果不确定时转人工、失败还是允许重试？ | 未明确前不得把失败或缺失结果当作通过；业务成功与 AI 失败独立 |
| 长任务与恢复 | 用户是否需要取消、改稿重提、等待超时或版本变更后重审？ | 跨请求等待采用持久化流程，取消保留已提交事实；工程恢复机制无需另问用户选哪个库 |
| Agent/MCP/外部 API | 开放哪些操作、给哪类客户端？读取哪些字段？写操作如何确认？ | 分开记录应用内 Agent、远程 MCP、页面 WebMCP 的允许集合；沿用已答选择，不从注册能力推断已授权暴露 |
| 共享能力与交付 | 通知谁、通过什么渠道？确有多种业务方案时确认；外部部署或全量浏览器验收按当前授权要求处理 | 复用设置/字典/文件/通知；本地测试不代替上线，不重复索要已授予的权限 |

涉及权限扩大、自动发布、对外发送敏感材料等关键答案未定时，相关行为保持未开放，继续完成契约草案、无关原子能力和测试准备。安全默认值应公开说明，不能把默认值说成用户已选择。

## 编码前的最小架构决策

按任务规模简写；纯展示变更只记录受影响项。复杂流程建议保存在功能设计文档，避免只存在于聊天。

| 决策 | 应记录的内容 |
|---|---|
| 业务与状态 | 角色、起止状态、人工节点、失败/取消/重提语义、公开时点 |
| 能力与事务 | 需求动作对应的已有能力/版本；复用、组合、扩展或新增及原因；Layer、读写对象、权限/风险、事务边界与 Outbox |
| 运行机制 | 普通 Go 组合、Workflow、Graph、ADK 或单次模型调用；使用/不使用理由 |
| 契约与来源 | 输入输出及事件来源；现有 Schema/生成命令；结构化 AI 结果、版本和原因字段 |
| 接入与数据 | UI、后台、Agent/MCP 允许集；人工任务入口；正文/凭证在审计、检查点和模型中的边界 |
| 验证与缺口 | 各条分支、权限拒绝、恢复和用户可见结果的断言；现有框架缺口与未定项 |

## Eino 选型与人工节点

| 条件 | 选择 | 验收证据 |
|---|---|---|
| 单个事务动作或无需暂停的同步聚合 | 原子能力或 Go 编排 Executor | Gateway 调用与事务测试；不强制包装 Workflow |
| 业务链跨请求等待人工/外部结果，或明确要求持久化恢复 | Eino Workflow 主干 | 实际启动版本化定义，等待时持久化，重建引擎后续接原结果 |
| 有界轮询、多轮复核或只读瞬态重试 | Eino Graph 子图 | 退出条件、重试分类和步数上限测试；没有循环不强加 Graph |
| 模型需选择受限工具、组织调查或多步决策；用户明确要求 Agent | Eino ADK Runner | 原生 Runner 执行、固定版本工具白名单与当前权限交集、迭代预算与拒绝测试 |
| 固定输入、一次分类或提取，不需工具决策且无明确 Agent 要求 | Eino 模型接口可以直接调用 | 明确称为模型分类，结构化输出校验；不宣称使用 ADK |

Workflow 不代表 Graph 和 ADK 必须同时存在。`Layer=orchestration` 也可以只是同步组合；`ai_runs` 是生命周期记录，不能证明使用 ADK。

业务人工任务与 Gateway 风险确认必须分别设计：后者允许执行一个高风险调用；前者表达谁对哪一版业务对象作出什么决定、驳回原因及处理时限。可以复用审批设施，但要证明任务权限、查询范围、决定和恢复语义吻合，不自动建立第二套通用审批服务。

当前编排器已有 Gateway 审批中断与恢复；这不证明已支持任意业务人工任务、外部信号或任意条件分支。现有 ADK 节点结果是 answer 文本对象，也不等于业务评审结果 Schema 已获保证。先读 spec、适配器及测试；不足时按需求扩展 Eino 集成与严格规格，或者明确说明尚未完成，不能造假节点/滥用风险审批顶替业务审核。恢复发布动作仍需原作者授权；审核决定使用审核人自己的身份记录，两者不能互相冒充。

## 文章发布评审：目标设计示例

本节是用户要求的目标与验收基准，**不是文章功能已完成改造的声明**。当前文章代码仍为投稿事件触发普通函数、直接模型分类、独立人工决定；下述 Workflow/ADK、独立人工任务页面与完整原因链需要另行实施和验证。

```text
作者点击发布 → 提交指定版本 → AI 评审中（尚未公开）
  → Outbox / Trigger → 启动评审 Workflow
    → 读取本次文章版本、规则检查、受限 ADK 评审
    → 服务端验证结构化结论与版本
       ├─ 无问题 → 状态已发布 → 流程结束
       └─ 有问题 / 不确定 / 失败 → 待人工评审 → 人工评审页面
          → 有权且非作者的审核人决定
             ├─ 通过 → 已发布 → 流程结束
             └─ 不通过 → 审核不通过 + 面向作者的原因 → 流程结束
```

Graph 仅在新增多轮复核需求时加入。不能先公开再评审。文章读取、评审写入与人工决定仍是模块能力，全部经 Gateway；状态修改与任务/事件的原子性按实际事务实现声明。Agent 只提出候选结论，不能给自己授予发布或审核权限。

结构化契约至少覆盖文章 ID/版本、评审结论、原因码、可展示原因与评审规则版本；人工决定另含通过/驳回及必填驳回原因，审核人由可信 Principal 提供。正文不进入事件、调用审计和普通 AI 轨迹；需要恢复的材料必须明确最小化、加密与保留边界。规则解析后无有效词条也属于无效配置，不能自动发布。

状态标识以该功能的迁移、实体与能力契约为准，不因为本示例中文标签另建第二套状态枚举。已审核版本之外的改稿不能复用旧结论；重提、取消与旧任务的处置先明确业务规则。

## 交付前需要证明的行为

- 功能的真实入口到达所选引擎，实际业务定义已注册；事件重投和用户重试不会重复创建流程或发布。
- AI 安全、问题、不确定、配置/模型失败分别到达正确状态；结构化结果缺字段、未知结论、版本不符时不能当通过。
- 人工队列只展示授权任务；作者自审、跨租户、读取他人草稿、重复/过期/旧版本决定均被拒绝；驳回原因在作者页面可见。
- 等待人工时重启可恢复；取消、权限撤销、改稿重提不会让旧决定继续发布。业务已提交事实不因 AI 失败被改写。
- 工具发现和调用都遵守各渠道允许集合；敏感只读结果不因模型转述、运行记录或 Workflow 检查点绕过保密要求。
- 页面有针对性的 RTL 交互断言，数据库边界用隔离 PostgreSQL，Eino 路径用真实引擎和可控模型验证；用 stub 替换整条评审函数只能证明路由，不能证明 ADK 接入。通用生命周期示例通过不等于文章功能通过。

以上按实际功能选择用例，不为无关动作增加等待、审核或模型。具体门禁与执行节奏仍以 testing.md 和现行 AGENTS 为准。

## 项目 Skill 与规则维护

项目 Skills 位于 .agents/skills，另保留完整官方 goa-service-designer。元数据负责触发，正文指导流程；更细约束位于对应子目录 AGENTS，背景原理位于 docs。新增 Skill 应描述具体触发场景和不应激活的边界，避免为每个依赖复制手册。

官方 Goa Skill 通过 `npx --yes skills add goadesign/goa --skill goa-service-designer -a codex --yes --copy` 安装，来源/hash 在 skills-lock.json；项目自产 Skill 由 Git 跟踪，不伪造成上游安装项。官方指南：https://goa.design/docs/ai-development/ 。生成器依赖仍以 go.mod tool 固定版本，升级 Skill 不隐式升级服务依赖。

维护 Skill 时使用可用的 skill-creator 和官方 quick_validate.py 进行作者校验；仓库 CI 自带 check-rules，不依赖作者机器上的全局脚本。新/移动规则同步 agent-policy.json 与任务矩阵。不要直接改上游 Skill 来隐藏项目约定，把本地约定放自己的 AGENTS/Skill。

规则不自动授予部署、生产数据操作、凭证或外部消息权限；按用户授权范围持续完成工作。出现局部不明确时先推进不依赖它的部分，不把规则文档变成重复确认流程。

## 失败与可信汇报

读取完整错误，修手写源/夹具，生成问题回源契约或生成器配置。相同根因最多连续三轮盲修，之后说明证据与选项；不得跳过/删除/弱化检查。同源权限和 SQL 隔离测试是实际安全证据，前端按钮隐藏不是。

生成和浏览器验收串行，避免 Vite 热更新干扰。普通 Playwright 测试资产与 CI 独立于 MCP；失败保留退出码、screenshot、Trace 和 console/network。已配置、本地通过、远程 CI 通过分开报告。

编排任务先读取 [完整示例](orchestration-example.md)、[Schema 路线](agent-generation-plan.md)。流程 Go 源 → generate-workflows → 候选定义结构/语义检查 → Eino 编译 → Gateway 授权 → 真实数据库行为测试。生成 JSON 只用于查看/检查，当前不能从远程注册任意流程。
