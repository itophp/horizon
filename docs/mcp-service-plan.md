# 账号级远程 MCP 服务实现方案

日期：2026-10-30。状态：首阶段开发与验收中。实际实现边界见 [ADR 011](decisions/011-remote-mcp.md)，使用与恢复见 [操作指南](mcp-operations.md)。OAuth 和写操作仍属于后续阶段。

## 目标与现状

增加可供 WorkBuddy、Codex 等客户端访问的账号级业务 MCP 服务。每个账号管理自己的访问 Token，自选开放工具、部门上下文和有效期；无需打开业务网页也可调用。沿用单 Go 服务、Goa、Casbin、可信 DataScope、PostgreSQL 和现有前端，不创建独立微服务或第二套业务权限。

现有 [ADR 009](decisions/009-webmcp.md) 是本机配对页面工具：依赖活动网页、短期配对密钥、stdio 转发与安装脚本。保留它用于页面操作和诊断；新增远程 `baseline-business` 与现有 `baseline-web` 使用不同名称、凭证和生命周期。可复用安装中的备份/合并策略，不能把本机配对密钥升级成账号凭证。

## 市场调研与需求补全

以下为官方样本的能力比较，不是市场占有率排名。调研日期同上；官方协议 latest 当前指向 2026-07-28，不能把旧版会话协议当作当前唯一实现。

| 官方样本 | 已公开的能力/方式 | 本项目采用的要求 |
|---|---|---|
| [GitHub MCP](https://github.com/github/github-mcp-server) | 按 toolsets 或单工具选择仓库、issue、PR 等能力 | 模块化工具目录、精确允许列表；不把所有后台 API 自动发布为工具 |
| [Linear MCP](https://linear.app/docs/mcp) | 检索/创建/更新任务与项目；Streamable HTTP；OAuth 或 Bearer；独立只读方式 | 远程入口、只读模式、个人凭证、按读写分级 |
| [Notion MCP](https://developers.notion.com/guides/mcp/overview) | 托管远程服务，OAuth 后读取/更新用户可访问内容 | MCP 权限不得超过本人业务权限；后续增加 OAuth |
| [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) | stdio/远程 HTTP、环境变量 Bearer、OAuth 登录 | 官方 CLI 配置或本机助手；密钥不进入安装命令 |
| [WorkBuddy 连接器](https://open.workbuddy.cn/docs/connector) | MCP + Skill；远程 HTTPS；OAuth 或用户填写 Token | 提供连接器包、Token 表单和使用指南；Token 模式官方最低版本 4.23.0，所用字段另核版本 |
| [MCP 规范](https://modelcontextprotocol.io/specification/2026-07-28) | 工具、资源、提示模板及协议协商 | 先实现工具；资源/提示模板按实际场景扩展，不能依赖所有客户端支持 |

据此增加的基础需求：工具目录与能力说明、权限/风险标签、有效期与撤销、按平台独立 Token、调用审计、分页与结果上限、超时/限流、稳定错误、健康诊断、版本兼容、真实客户端验收。长期任务、写入审批、批量导出和 OAuth 分阶段建设，不以“常见能力”为由自动接入所有功能。

## 产品范围

### 第一阶段必须交付

1. 远程 HTTPS `/mcp`，标准初始化/能力协商、工具发现和调用、错误与取消处理。按选定 SDK/协议版本实现，不手写 JSON-RPC 状态机。反向代理支持相应响应流、超时和大小限制。
2. 登录后“个人设置 → MCP 接入”：服务地址、工具目录、Token 列表、创建/轮换/撤销、Codex/WorkBuddy 接入卡片、连接诊断和本人调用记录；沿用当前设计系统，文案同步 en/zh-CN。
3. 每人可创建多个具名 Token，建议每个平台独立一个；创建时选择部门、工具组/具体工具、只读模式、到期时间。建议默认 30 天，最大 90 天；均为待实现产品默认值，不是现有策略。新工具不因加入工具组而自动获得旧 Token 授权：签发时固化允许工具集合。
4. 首批工具建议：`context_get`（本人及绑定部门的最小上下文）、`capabilities_list`（当前有效工具）、已授权的字典选项查询、本人通知列表与详情。只读账号查询可按需求追加，必须使用现有字段投影；敏感设置、角色授权、密钥管理不默认开放。
5. 自测流程：验证连接 → 获取目录 → 调用最小只读工具 → 展示最近成功或稳定错误码；不能只凭配置文件写入就提示连接成功。
6. 安全基础与审计随第一阶段交付，不能等写操作阶段再补。本人 Token 管理不等于能调用任意业务能力；管理员可基于独立正式权限紧急撤销 Token，不能读取他人明文或代发其 Token。

用户已确认首批采用上述推荐只读集合。

### 后续分阶段

- 第二阶段：用户明确选择的创建/修改/确认/发送等工具；幂等键、服务端预览与确认、风险分级、批量上限、失败恢复。
- 第三阶段：标准 OAuth 授权码 + PKCE、资源发现、授权同意页、短期访问令牌与刷新撤销；平台连接器上架按平台审核单独处理。
- 按实际需要再加 Resources、Prompts、长任务/进度与取消、只读检索聚合。新增这些入口仍执行同一权限与字段边界。
- 不默认提供任意 SQL、shell、通用 HTTP 代理、任意文件路径、全库导出、权限修改或对外消息发送工具。

## 架构与契约

建议调用链：客户端 → HTTPS `/mcp` → MCP Token 验证 → 实时 Principal/部门重建 → 工具注册表 → 原应用服务授权 → 原 Repository/sqlc 范围查询。

在 `services/api/internal/mcp` 增加协议适配、注册表和 Token 用例，传输入口在现有 Go 进程挂载；业务逻辑仍留在 identity/governance 等原服务中，MCP 不能直接调用裸 dbgen 或绕过用例。业务写入、审计和幂等复用原事务边界。

唯一业务与 Token 管理 API 源仍为 `services/api/design`。新增 `design/mcp.go` 定义本人 Token 创建/元数据列表/撤销/轮换、工具目录和诊断等管理契约，生成前端 SDK；建议路径 `/api/mcp/tokens`、`/api/mcp/capabilities`，具体按现有 Goa 路由风格确定。轮换默认原子撤销旧 Token 并创建新 Token；需无中断交接时显式签发第二个 Token，不能暗设无限宽限。

MCP 协议消息由官方 SDK 实现，是独立传输适配，不另造业务 DTO。工具注册表仅维护工具名/说明/版本、对应 Goa 用例、输入输出 schema 映射、resource/action、风险、幂等和限制；通过转换或生成复用源类型，并用契约测试防漂移。`/mcp` 不能被误当普通 OpenAPI CRUD 自动生成；新增协议契约文件必须明确它与 Goa 业务源的边界。

选用 [官方 Go SDK](https://github.com/modelcontextprotocol/go-sdk) 与现有 Go 栈一致。已固定 v1.8.0，核对该 tag 的最低 Go 1.25.0、协议协商范围和 LICENSE，记录于 `docs/versions.md`；当前上游说明包含 Apache-2.0/MIT 历史代码，不能仅凭项目名称写成单一许可证。依赖安装与已验证范围见 [验证记录](mcp-verification.md)，不宣称所有客户端操作均已验收。至少对目标客户端支持的版本做矩阵验收；2026-07-28 与旧版协商/会话语义有区别，不能跨版本强套 session/list_changed 行为。

## Token 与授权

Token 建议 `前缀 + 非秘密随机标识 + 256 位随机秘密`。只在创建/轮换响应中显示完整值一次；数据库存随机秘密的不可逆摘要和检索标识，常量时间比较。摘要不返回 SDK/UI，不保存可恢复明文。列表仅显示名称、前缀/尾部提示、部门、工具集合、创建/到期/撤销、最近使用时间。创建响应禁止缓存，浏览器仅暂存在内存，关闭弹窗清除；不能写 localStorage、URL、剪贴板自动同步或业务日志。

建议表：`mcp_tokens`（租户、本人、绑定部门、摘要、有效期、撤销时间）、`mcp_token_tools`（固化允许工具）、`mcp_call_audits`（本人/Token ID、工具/版本、部门、结果码、耗时、request ID；无原始参数/结果）。所有管理 SQL 显式本人及租户条件；管理员撤销使用独立入口/权限和审计。过期/撤销用数据库时间判断，Token 数量与审计保留期有界并文档化。

有效能力 = Token 固化工具集合 ∩ 当前账号在绑定部门的正式权限与数据范围 ∩ 当前工具启用规则。第一版不继承临时提权；账号禁用、退出部门、角色撤销、Token 到期或撤销后，新请求立即拒绝。不能把签发时权限快照当长期授权；撤销后的长流/长任务在后续业务步骤与写入提交前复查。首版每请求查询数据库，避免跨实例缓存导致撤销滞后。

Token 自管理以已登录本人会话 + 原 Origin/CSRF 与敏感操作重新认证为边界，不依赖业务管理员角色；MCP Token 自身不能创建/读取/轮换 Token。部门和 owner 以凭证绑定身份为准，工具参数不能切换身份或跨部门合并角色。

工具目录按有效权限过滤，但猜测隐藏工具名的直接调用仍须服务端拒绝。分页/关联/下载/聚合与普通 API 保持范围一致。只读模式同时禁止调用写工具，不能只隐藏目录。文件读取复用绑定鉴权，不能把个人 Token 拼入下载链接。

仅接受 Authorization Bearer；网关/应用/追踪系统均脱敏。禁止 query Token、Token passthrough 和接受其他服务签发给别的 audience 的凭证。严格 Host/Origin（包含非法来源拒绝，非浏览器无 Origin 客户端按策略接受）、TLS、请求大小、工具超时、账号+Token+IP 有界限流；IP 只信任配置代理链。协议 session ID 不替代认证，不跨账号复用结果或连接。

个人 PAT 是客户端配置凭证的产品模式，不等于已实现 MCP OAuth 授权规范。后续若宣称支持标准授权，必须完整实现资源元数据/发现、PKCE、resource/audience 校验、redirect URI 限制和撤销测试，依据[官方授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)及所选新版条文核对。

## 一键接入的实际边界

远程网站不能直接修改用户电脑的 Codex/WorkBuddy 配置。支持两条路径，UI 必须准确区分“已生成”“已安装”“已连接”：

- 已运行受信任本机助手：用户点击选定平台，短时单次配对绑定来源/账号/服务地址/目标平台；本机展示目标配置并确认后，通过官方 CLI/平台支持机制合并配置。凭证经受控通道存入系统凭据存储或 0600 本地文件，配置仅引用；安装请求不能提交任意命令/路径。备份原配置、保留其他 MCP、失败展示已完成部分和恢复方式；非法配置拒绝覆盖。
- 没有助手：生成无秘密配置、官方 CLI 指令/连接器包，并引导在客户端输入 Token；这是引导导入，不能宣传为已一键安装。下载包、二维码、分享链接不含真实 Token。OAuth 阶段可减少手动填密钥。

Codex 远程配置示例：

```toml
[mcp_servers.baseline-business]
url = "https://YOUR_HOST/mcp"
bearer_token_env_var = "BASELINE_MCP_TOKEN"
```

配置引用环境变量不等于 GUI 应用已获得该变量；本机助手需验证实际客户端进程环境，或使用从系统凭据存储读取的 stdio 适配器，不能把 Token 填进 CLI 参数来规避问题。

WorkBuddy 推荐生成官方连接器结构：`connector-meta.json`、`mcp.json`、`token-schema.json`、图标及运行时 Skill。采用 `auth_mode: token`，模板通过 Authorization header 引用表单字段；私有部署地址需 HTTPS 校验。所用字段与最低客户端版本实施时再次核对。现有 `.workbuddy/mcp.json` 本机合并只作为已测试版本的助手路径，不能冒充官方通用 deeplink。未查证平台安装协议前不编造 URL scheme；客户端升级后重新兼容验收。

面向未来功能开发的工具设计与维护 Skill 在 `.agents/skills/baseline-mcp-development`；它指导按业务用例创建工具、处理需求变更和验证权限，不以实施 MCP 基础服务为主要用途。面向客户端使用的运行时 Skill 应单独打包，说明工具用途、分页、授权错误、读写风险和确认流程，不能把工程规则作为运行时操作说明直接分发。

## 功能开发与需求变动流程

每个功能批次在需求澄清时主动集中询问：是否开放 MCP；开放哪些查询/详情/创建/修改/删除/导出/批量操作；哪些客户端；是否只读及需要什么确认。已明确选择的沿用，不逐文件重复问。用户未回答时继续不依赖选择的开发，记录待定，不能默认开放写入；已有 MCP 工具遇到字段/权限/流程变更，仍必须维护或明确禁用，不能用待定跳过兼容和安全修复。

维护能力矩阵：用例 → 工具名/版本 → resource/action → 字段/范围 → Token 授权 → 风险/确认 → 测试。新增功能可选择不开放，并记录原因。需求变动同步源契约、工具 schema、服务、运行时 Skill、客户端配置示例及允许/拒绝测试。破坏性改动引入新版本或弃用期，旧工具不得悄悄改变参数语义。

写操作未来采用服务端预览/确认凭证：绑定本人、部门、Token、工具、规范化参数摘要和短时有效期，单次消费；授权变更或参数变化即失效。客户端确认提示及 MCP annotations 仅辅助体验，不能作为服务端批准证据。

## 实施顺序与验收

| 批次 | 实施内容 | 验收重点 |
|---|---|---|
| A | 确认首批工具/只读范围；固定 SDK 与协议/客户端版本；Goa/SQL 源设计 | 能力矩阵、版本/许可证、源契约评审 |
| B | Token 表/管理 API、身份适配、工具注册、远程入口、审计/限流 | 真实隔离 PostgreSQL；本人/跨账号/跨租户/范围/撤销/禁用负向测试 |
| C | 个人 MCP 页面、en/zh-CN、两平台配置/助手与运行时 Skill | 创建仅显示一次、轮换撤销、备份恢复、无秘密配置和错误状态 |
| D | 首批只读工具、生产代理、真实两平台端到端 | 各平台初始化→目录→调用→撤销拒绝；关闭网页后仍可用；原 WebMCP 回归 |
| E | 单独确认的写工具与 OAuth | 幂等/确认重放/过期/撤权/回滚及标准授权互通 |

代码批次依赖顺序为 SQL/Goa → generate → 应用/协议 → SDK/UI → check-generated → 浏览器与客户端；阶段统一 ci-fast，追加 test-security（含真实数据库）、协议测试、相关 Playwright 和 `pnpm webmcp:test`。发布候选运行完整 ci。新增 MCP 专项命令需实施时接入 Makefile/CI；目前不存在，不报告运行成功。

负向验收至少覆盖：无效/过期/撤销 Token、A 管理 B Token、越权工具直接调用、篡改部门/租户/owner、禁用与归属移除、敏感字段泄漏、readonly 调写、批量范围混入、日志/下载/安装包泄密、恶意 Origin/Host、请求过大/超时/限流、跨身份流/会话、轮换并发与审计失败。客户端缺失应记未执行，不能以模拟器代替真实平台通过。

第一阶段完成标志：每个账号独立管理 Token；两平台至少各一条真实可用接入路径；网页关闭仍可调用首批只读工具；原权限不放宽；撤销实时生效；配置与审计无明文秘密。

## 持久化流程工具

workflows_list / workflows_get / workflows_run / workflows_cancel 对应 orchestration.workflow 能力。Token 工具集合与当前 read/run/cancel 权限取交集；旧 Token 不增加工具。启动/取消为高风险自动化调用，通过 Gateway 审批，不因 MCP 的提示元数据绕过授权。详见 [编排方案](orchestration-plan.md)。
